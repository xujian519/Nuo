# 决策记录（ADR）

> 每条只写"为什么"，不重复"做了什么"（做了什么见 `DESIGN_SPEC.md`）。
> 格式：背景 → 决策 → 代价 → 被否方案。

---

## ADR-001 · 用「纸 + 印」而不是第二个 Grok

**背景**：目标是做对标 Grok bot 的个人智能体。行业默认解法是黑底、发光、大留白。

**决策**：暖灰宣纸做底，唯一彩色是印泥朱红，且只出现在「存在」与「承诺」两个时刻。

**代价（诚实的部分）**：
- 放弃"科技感"这个最容易传递的信号，需要靠别的东西建立"这是智能体"的心智——我们用光球的呼吸节奏来承担，这是**更高成本**的一条路（纯视觉比光效更难做对）。
- 暖灰在深色环境（夜间、暗房）里不如纯黑沉浸。
- 需要一次性重构配色（`CustomTheme` 两个默认预设 + 引导页独立调色板）。

**为什么仍然选它**：
1. 黑底发光已经变成品类通用皮肤，**无法提供识别度**，而我们缺的正是识别度。
2. 纸的暖调与"本地、私人、可归档"在直觉上同源——这是 Nuo 相对云产品的唯一结构性差异。
3. 8 小时工作日的可视舒适度更好。

**被否**：Liquid Glass 原生玻璃（贴合系统但个性最弱，且和现有暖灰体系冲突最大）。

## ADR-002 · 不做聊天气泡

**背景**：所有对话产品都是左右气泡。用户也"预期"这样。

**决策**：你的话收进卡片（左侧 2pt 朱红细线），它的话直接长在画布上，无容器。

**理由**：气泡是即时通讯语法，暗示"两个人在发短消息"。智能体的回答是**文档**——能长、有代码、有表格、能被引用、能被回看。把文档塞进 70% 宽的气泡是形态错误。

**代价**：
- `ThemeProtocol` 里 11 个气泡字段（`bubbleCornerRadius`、`userBubbleOpacity`…）变成死字段，要么删要么标注废弃。删是破坏性的（用户主题 JSON 里可能有值）→ **保留但停止读取**。
- 用户第一次看会觉得"不像聊天软件"，需要空状态与第一条回答的排版来补偿。

## ADR-003 · 令牌向现有常量对齐，而不是重新设计

**背景**：真实代码里字号 4,893 处字面量、间距 3,344 处、圆角五档并存（14/20/10/8/3）。按"重新设计一套"会把返工量推到不可交付。

**决策**：新令牌**尽量采用现有默认值**——body 15、caption 12、code 13、title 26、heading 18、控件圆角 8、dock 20、卡片 12。只在必要处改动（新增 ink3/ghost 的对比度修正、新增 amber 与呼吸类动效）。

**代价**：这套令牌的"音节"不是纯理论最优（比如 12px 对中文偏小，13px 更舒服），但**一致性收益 > 单点最优**。

**被否**：全量重设字阶（4,893 处 + 消息层 AppKit `NSFont` 另起一套，等于重写渲染层）。

## ADR-004 · 存在态先用 SwiftUI，Metal 与 shader 延后

**背景**：仓库里有一份完整的 `OrbShader.metal`（68 行 fbm 噪声 + 双高光 + rim），但**全仓 0 引用、未进 pbxproj**。看起来是"已经做好一半"，实际是死代码。

**决策**：先交付纯 SwiftUI 的 `PresenceOrb`（`TimelineView` + 渐变层 + 正弦呼吸），不依赖 Metal。

**理由**：
1. 存在态是**全新品类的屏**，它的风险在"节奏对不对"，不在"渲染快不快"。用 SwiftUI 可以在两小时内迭代十版节奏；走 Metal 要先把 pbxproj、`.colorEffect` 接线、首次编译调试全部打通。
2. 30fps 的 TimelineView 只改 opacity/scale，Core Animation 层，**不触发 SwiftUI 重排**，在 220pt 尺寸下开销可以忽略。
3. 如果最终需要更强的流体感，SwiftUI 版的分层结构（halo / rings / core / blobs / glint）可以直接映射到 shader 的输入。

**代价**：失去了 noise-based 的有机边缘，球体边缘是数学圆。这在小尺寸（16–28pt）下无差别，在 220pt 下会略"规整"——是可接受的取舍。

## ADR-005 · 三个透镜的侧栏，而不是二选一

**背景**：左栏现在是 `Agents | Projects` 双透镜，历史会话搬到了右侧 inspector。这是一个为"多智能体协作"做的结构，代价是把最高频入口（继续上次）藏到了第二层。

**决策**：三透镜 `会话 | 智能体 | 项目`，默认「会话」；`history` 面板保留，降级为「完整历史 + 搜索」。

**代价**：多一个 lens = 多一次点击才能到 agent 列表；需要重新排布侧栏默认宽度（260 → 上限 380）。

**为什么值得**：个人智能体的 80% 动作是"接着上次说"。把它放在第一屏的左侧，比任何品牌视觉都更能减少每天的摩擦。而且复用了现有 `SidebarLensBar`，成本是一个 enum case。

## ADR-006 · 不自绘红绿灯

**背景**：原型里有"静止为墨点、悬停浮现系统色"的红绿灯方案，视觉上很好。

**决策**：**不实施。** 保留系统红绿灯与 `NSToolbar`。

**理由**：自绘需要 hack `standardWindowButton` 的 tint 与 layer，跨 macOS 版本必碎，而收益只是"更好看一点"。这个界面里已经有足够多的品牌时刻（印章、光球、句读），不需要在窗口装饰上再赌一次系统兼容。

**被否方案**：隐藏标准按钮 + 自绘（视觉最优，维护最差）；把红绿灯整体移到侧栏顶部（违反 macOS 用户肌肉记忆）。
